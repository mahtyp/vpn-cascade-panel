# Серверные скрипты VPN Cascade Panel

Эти скрипты входят в универсальную панель каскада. При обычной работе предпочтительнее
использовать графические действия панели: мастер установки, «Протоколы → Схема»,
обновления и резервные копии. Команды ниже — для опытного администратора,
восстановления и проверки. Выполнять только на своих серверах.

## Архитектура

- **Вход**: 3X-UI (Xray) с клиентскими входящими, туннели AmneziaWG `wgN`,
  а для резервного Sudoku — прокси Mihomo, передающий соединения на выход.
- **Выход**: AmneziaWG `awg0` и/или сервер Sudoku. Поддерживаются входы и выходы
  с несколькими каналами и настраиваемыми порядками резервирования.
- **Связь**: Xray выбирает исходящие AWG/Sudoku по цепочке `fallbackTag`.
  У отдельного правила маршрутизации может быть свой порядок.

Примеры ниже используют **только условные названия** `EntryA`, `ExitA`.
Значения IP, ключей и имена реальных серверов в GitHub публиковать нельзя.

## Бэкап и резервный вход

| Скрипт | Место запуска | Назначение |
|---|---|---|
| `vpn-backup.sh` | Существующий вход | Архив 3X-UI, Mihomo, AWG и системных настроек |
| `vpn-restore.sh` | Новый вход | Восстанавливает вход из архива, создаёт отдельные AWG-клиенты |
| `vpn-awg-common.sh` | Рядом с установщиками | Общие функции AmneziaWG; напрямую не запускать |
| `vpn-entry-new.sh` | Через мастер | Подготовка нового входа |

Пример:

```bash
bash /root/vpn-backup.sh
# Архив передать на новый сервер по защищённому каналу.
bash /root/vpn-restore.sh /root/ИМЯ_АРХИВА.tar.gz
```

Архивы **содержат секреты** (ключи, конфигурации, клиентские данные). Не прикладывайте
их к публичным Issues, логам или сообщениям о проблеме. При смене IP серверу понадобится
собственный корректный SSL-сертификат. Резервный вход получает настройки на момент
снятия бэкапа, дальнейшие изменения автоматически не синхронизируются.

## Новый выход: AmneziaWG и Sudoku

| Скрипт | Место запуска | Назначение |
|---|---|---|
| `vpn-exit-setup.sh` | Новый выход | Настройка выхода с AWG и Sudoku |
| `vpn-add-exit.sh` | Каждый выбранный вход | AWG-туннель, Sudoku/Mihomo и цепочка резерва |
| `vpn-pin-chain.sh` | Вход | Отдельный порядок каналов для выбранного правила |
| `vpn-reorder.sh` | Вход | Изменение порядка звеньев без добавления новых |
| `vpn-unlink.sh` | Вход | Удаление выбранной связи с проверкой и копией |

```bash
# На выходе:
bash /root/vpn-exit-setup.sh
# На каждом входе после установки и проверки выхода:
bash /root/vpn-add-exit.sh ExitA IP_ВЫХОДА
```

При изменениях 3X-UI перед записью создаётся резервная копия базы.
Проверяйте план, доступность альтернативных каналов и результат до/после.
Не запускайте массовые изменения одновременно на всех входах.

## Обслуживание Sudoku и Mihomo

| Скрипт | Назначение |
|---|---|
| `vpn-sw-update.sh` | Обновляет Sudoku или Mihomo с проверкой и откатом |
| `vpn-sudoku-direct.sh` | Переводит Sudoku из `sudoku-sing-box` в отдельную службу |
| `vpn-remove-client.sh` | Удаляет AWG-клиентов входа на выходе; `--dry` — просмотр |

Секреты Sudoku остаются на серверах и в локальном хранилище панели.
Публичный исходный код — это интеграция, **не экземпляр рабочей конфигурации**.

## Стенд и проверка

`dev/testbed.sh` создаёт только фиктивные входы/выходы на Linux-машине
с заглушками 3X-UI, AWG и Sudoku/Mihomo. **Не запускать на боевом сервере.**
Перед релизом проверить несколько разных схем: только AWG, AWG+Sudoku,
основной/резервные каналы, добавление/удаление, отказ и откат.
