# Панель каскада

Веб-панель на вашем Windows-компьютере для VPN-каскада **вход → выход**: входные серверы с 3X-UI
(Xray, VLESS Reality), выходные — с AmneziaWG, между ними туннели AmneziaWG и цепочка резерва из
балансировщиков 3X-UI. Панель заходит на серверы по SSH и показывает всё в одном месте: живы ли
серверы и каналы, куда сейчас идёт трафик, что режут по пути, как сервер видят сайты. Она же
разворачивает новые выходы и копии входов, делает бэкапы и обходы для отдельных сайтов.

Сама по себе панель только смотрит. На серверах что-то меняется, только когда вы нажимаете кнопку
действия и подтверждаете его (перед правкой — копия, при сбое — откат) или сами набираете команды в
консоли. Страница открывается только на этом компьютере; пароли root хранятся в Диспетчере учётных
данных Windows.

## Что нужно

- Компьютер с Windows 10/11, Python 3 и Git (установка ниже). Сборки и Docker не нужны.
- **Входы** — серверы с [3X-UI](https://github.com/MHSanaei/3x-ui): входящий для ваших устройств,
  исходящие `AWG-ИМЯ` (freedom с `sockopt.interface = wgN`) и балансировщики с `fallbackTag` —
  цепочка резерва. Туннели до выходов — конфиги `/etc/amnezia/amneziawg/wgN.conf` (`Table = off`).
- **Выходы** — серверы с AmneziaWG: сервер `awg0` модулем ядра (так ставит мастер «Новый сервер»)
  или контейнер приложения AmneziaVPN в Docker.
- Доступ root по SSH с паролем. Ubuntu 24.04 — для установки новых серверов мастером; уже
  работающие серверы панель просто читает.

Уже есть свой каскад — добавьте серверы на странице «Серверы и пароли», панель сама найдёт туннели,
цепочку и правила. Нет — заведите один вход с 3X-UI, а выходы ставьте мастером «Новый сервер»: он
сам поднимет AmneziaWG на выходе, туннель на входе, исходящее и звено в цепочке 3X-UI.

### Как устроен каскад

```
телефон ─VLESS─▶ вход (3X-UI) ─┬─ wg0 ─▶ выход 1 (awg0) ─▶ интернет
                              ├─ wg1 ─▶ выход 2 (awg0) ─▶ интернет   (резерв)
                              └─ wg2 ─▶ выход 3 (awg0) ─▶ интернет   (резерв)
```

Трафик идёт по первому исправному звену цепочки: 3X-UI сам проверяет исходящие (observatory) и
переходит к следующему, если выход упал. Отдельным правилам (например, адресам Telegram DC5 или
обходу для сайта) можно дать свою цепочку. Входов может быть несколько — резервные копии основного
с теми же клиентами; панель сверяет их с основным.

## Установка (Windows 10/11)

1. Установите Python 3 с [python.org](https://www.python.org/downloads/). В установщике
   отметьте **Add python.exe to PATH**. (На старых Windows 10 нужен классический установщик
   `python-3.13.x-amd64.exe`, а не «Python install manager».)
2. Установите Git с [git-scm.com/download/win](https://git-scm.com/download/win) — все
   вопросы установщика оставьте как есть, просто «Next».
3. Нажмите Win+R, введите `cmd`, Enter. В чёрном окне выполните:
   ```
   cd %USERPROFILE%
   git clone https://github.com/mahtyp/vpn-cascade-panel.git
   ```
   Панель скачается в папку
   `C:\Users\<вы>\vpn-cascade-panel`.
4. Дважды щёлкните `start.bat` в этой папке. В первый раз он поставит библиотеки (paramiko
   для SSH, keyring для паролей, pystray и pillow для значка), потом откроет в браузере
   `http://127.0.0.1:8787`. Окно `start.bat` закроется само: панель уходит в трей.
5. Откройте **Серверы и пароли** → **+ Добавить сервер** для каждого входа и выхода,
   введите пароль root → **Сохранить пароль и проверить вход**.
6. Вернитесь в **Обзор** → **Проверить всё**.

**Перенос на другой компьютер или в другую папку.** Выйдите из панели (значок в трее → **Выход**),
скопируйте в новую папку `servers.json`, `known_hosts`, `history.db`, `checks.log` и папку `backups` —
так сохранятся серверы, настройки, история и бэкапы. Пароли на другом компьютере введите заново
(они в Диспетчере учётных данных Windows). Запустите `start.bat` в новой папке — автозапуск сам
переключится на неё.

Панель работает, пока в трее (у часов) есть её значок, и сама проверяет всё раз в 5 минут
(Telegram DC — раз в 30 минут). Это и всё остальное меняется на странице **Настройки**.

## Настройки

Страница **Настройки** в меню слева. Всё сохраняется в `servers.json` и действует сразу после
**Сохранить** (кроме порта — он после перезапуска панели). Под каждым полем написано
стандартное значение; кнопка **Вернуть стандартные** возвращает их все разом.

- **Проверки** — как часто проверять серверы и каналы, как часто Telegram DC; с какой
  задержки канал считается медленным; сколько ждать ответа; адрес, через который проверяется
  канал; когда рукопожатие AWG считается старым.
- **Пороги** — с каких процентов CPU, память и диск становятся жёлтыми и красными; сколько
  свободного места считать мало; за сколько дней предупреждать о сертификате панели.
- **Telegram** — какие DC и по каким IP проверять с выходов.
- **Сравнение входов** — какие два входа сравнивать и делать ли это при каждой проверке.
- **Бэкап** — чей, как часто, сколько архивов хранить.
- **История** — сколько дней хранить проверки для графиков.
- **Windows** — уведомления (все или только о красном), запуск вместе с Windows, порт панели.

Если ввели что-то не то (например, жёлтый порог выше красного), панель не сохранит и скажет,
что не так. Пока изменения не сохранены, внизу висит жёлтая полоса.

## Значок в трее и автозапуск

Цвет значка — общее состояние каскада:

| Цвет | Что значит |
|---|---|
| зелёный | всё в норме |
| жёлтый | есть замечание, но трафик идёт: упал один из каналов, выход недоступен, резерв отличается от основного входа, бэкап не удался |
| красный | вход недоступен или на нём не работает ни один канал |
| серый | данных ещё нет (только запустилась или не заданы пароли) |

Наведите мышь на значок — увидите, что именно не так. Когда становится хуже или снова
всё в норме, Windows покажет уведомление.

Щелчок по значку открывает панель в браузере. Правая кнопка — меню: проверить всё, сделать
бэкап, открыть папку бэкапов, включить или выключить уведомления и автозапуск, выход.

При первом запуске со значком панель сама включает **запуск вместе с Windows**: после входа
в систему она стартует без окна и браузер не открывает. Выключить — правой кнопкой по значку,
снять галочку «Запускать вместе с Windows». Если перенесёте папку панели, просто запустите
`start.bat` из нового места: путь в автозапуске обновится сам.

Windows 11 часто прячет новые значки под стрелку ^ у часов. Чтобы значок был виден всегда,
перетащите его оттуда на панель задач.

Есть и режим с чёрным окном — удобно, если панель не запускается и нужно увидеть ошибку: откройте папку панели, в адресной строке Проводника наберите `cmd`, Enter,
и в появившемся окне — `start.bat console`.

## Обновление панели

Новые версии появляются в GitHub. Подтянуть их можно тремя способами — любым:

- правая кнопка по значку в трее → **Обновить панель** (скачает и перезапустится сама);
- **Настройки** → **Версия и обновления** → **Проверить обновления** — там же видно, что
  изменилось;
- просто запустить `start.bat` — он проверяет обновления при каждом запуске.

Обновляется только код. `servers.json`, `known_hosts`, `history.db`, журнал и бэкапы в GitHub
не попадают и при обновлении не трогаются. Текущая версия написана внизу меню слева.

## Что где хранится

| Что | Где |
|---|---|
| Список серверов и все настройки | `servers.json` в папке панели (в GitHub не попадает) |
| Пароли root | «Диспетчер учётных данных» Windows → Учётные данные Windows → `vpn-dash` |
| Ключи серверов (защита от подмены) | `known_hosts` в папке панели |
| Журнал проверок | `checks.log` в папке панели |
| История проверок для графиков (30 дней) | `history.db` в папке панели |
| Бэкапы | папка `backups` в папке панели |
| Итоги установки новых серверов | папка `secrets` в папке панели (в GitHub не попадает) |
| Журналы установок и проверок мастера | папка `jobs` в папке панели |
| Вывод панели без окна (для разбора ошибок) | `dash-run.log` в папке панели |
| Автозапуск | реестр: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, значение `vpn-dash` |

Страница открывается только с этого компьютера (адрес 127.0.0.1); запросы с других сайтов
панель отклоняет.

## Как читать страницу

- **Каналы до выходов** — для каждого входа все туннели AWG до выходов, в порядке
  цепочки балансировщиков из 3X-UI. «Трафик здесь» — первый исправный канал в цепочке.
  Канал зелёный, если ответ пришёл с IP своего выхода быстрее 2 секунд; жёлтый — медленнее;
  красный — нет ответа или ответил не тот сервер.
- **Мини-график у канала** — последние сутки, 48 столбиков по полчаса: высота — задержка,
  красный столбик — в эти полчаса был сбой. Рядом — доступность за сутки в процентах.
  Нажмите на график — откроется подробный за 24 часа, 7 или 30 дней с медианой и числом сбоев.
  Ячейки Telegram DC тоже нажимаются; если за сутки DC был доступен меньше чем в 99,5 %
  проверок, под задержкой видно, сколько процентов.
- **Telegram с выходов** — с каждого выхода панель делает первый шаг входа в Telegram (MTProto),
  как приложение, и ждёт ответа DC. Время в ячейке — сколько занял этот шаг. «молчит» — порт 443
  открывается, но DC не отвечает (так режут по пути): Telegram через этот выход работать не будет.
  «нет» — до DC не открывается даже соединение. Если на выходе нет `openssl`, проверяется только порт.
- **Ресурсы сервера** — загрузка CPU, памяти и диска, а под ней — из чего сервер сделан: ядра,
  частота, виртуализация, процессор, объём памяти (и swap) и диска. Если хостер отдаёт часть
  процессора соседним машинам, появится «хостер забирает N% CPU»: от 5% жёлтым, от 15% красным —
  такой сервер под нагрузкой будет тормозить. Цифры — в момент проверки.
- **Сверка резервов** — при каждой полной проверке основной вход (первый в списке серверов)
  сравнивается с каждым резервным: клиенты, входящие, маршрутизация и балансировщики 3X-UI,
  параметры AWG-туннелей. Если вы добавили клиента или выход на основном входе и забыли
  повторить на резерве, тут появится строка вроде «Клиент «Х»: есть на основном входе, нет на резервном».
  Своё у каждого входа по задумке не показывается: имя входящего (входящие сравниваются по
  протоколу и порту), трафик, даты, `Address` и ключи туннелей. Ключи и пароли с серверов
  не передаются, сравниваются только их отпечатки.
  Если отличие так и задумано — кнопка **Это нормально**: строка уйдёт в «Принято как норма»
  и больше не будет мешать, пока значения не изменятся. Вернуть — кнопкой **Вернуть** там же.
- **Бэкапы** — кнопка **Сделать бэкап** запускает `server-scripts/vpn-backup.sh` на входе (по умолчанию первом), скачивает архив
  в папку `backups` и удаляет его с сервера. Автоматически — раз в 24 часа, пока панель
  открыта; хранятся 10 последних. Сервер, интервал и количество меняются на странице
  «Настройки». Если последнему архиву больше двух интервалов, метка станет жёлтой.
  В архиве все ключи сервера — храните папку `backups` как пароли.
- **Серверы** — нагрузка, службы, замечания: упавшая служба, старое рукопожатие AWG,
  сертификат панели, заполненный диск, нужна перезагрузка, недоступный DC Telegram.
  Кнопка **консоль** открывает терминал root на этом сервере прямо в браузере — то же, что
  Termius. Команды выполняются по-настоящему. Закрыть — кнопкой **Закрыть**; открытие
  консоли записывается в журнал. У выхода консоль сначала спрашивает, как зайти:
  **Напрямую** или **Через вход …** — панель заходит на вход, а оттуда по туннелю AWG
  на выход (если туннеля нет — по интернету с входа). Пригодится, если SSH с компьютера до
  зарубежного сервера начнут резать. Проверки панели при этом идут как обычно, напрямую.
- **Обновления** — кнопка **обновления** у каждого сервера в таблице «Серверы» (или плашка
  «обновлений: N» / «нужна перезагрузка» — она тоже нажимается).
  Откроется окно: какие пакеты обновятся (было → станет), какие из них — исправления
  безопасности, и что они затронут: «перезагрузка» (новое ядро), «SSH», «туннели AWG»,
  «Docker» (контейнеры Amnezia на выходе). Сверху — вывод: можно ставить или есть что учесть.
  «Отложены Ubuntu» — пакеты, которые Ubuntu выкатывает постепенно; их не трогаем, поставятся
  сами. **Проверить заново** обновляет списки пакетов (`apt-get update`). **Установить** —
  после подтверждения `apt-get upgrade` со старыми файлами настроек; если стоит галочка
  «перезагрузить, если потребуется», сервер перезагрузится и панель дождётся его. Потом панель
  сама проверит сервер и каналы, итог — в журнале. Окно можно закрыть, обновление продолжится.
  Обновляется один сервер за раз. Удобный порядок: сначала резервы и выходы, основной вход —
  когда VPN не нужен.
- **Журнал проверок** — внизу 10 последних записей; **Показать ещё** добавляет по 20,
  **Свернуть** возвращает к 10. Файл `checks.log` сам обрезается до 5000 записей.
- **Входы с этого компьютера** — открываются ли порты VLESS, подписки и SSH на входах
  так, как их видят ваши устройства.

Новые туннели панель находит сама: после `vpn-add-exit.sh` новый канал появится в списке
на следующей проверке.

## Как изменить или добавить сервер

Всё правится на странице **Серверы и пароли** (или кнопкой **изменить** у сервера в обзоре)
и сохраняется в `servers.json` — переживает перезапуск панели и обновление.

- Поменяли IP, порт, пользователя или роль → **Сохранить список**. Панель закроет старое
  SSH-соединение, сбросит старые результаты этого сервера и сразу проверит всё заново.
  Пароль остаётся прежним; если на новом сервере он другой — введите новый.
- Новый сервер: **+ Добавить сервер**, заполните название, адрес и роль, введите пароль и
  нажмите **Сохранить пароль и проверить вход** — список сохранится сам. id придумается
  из названия.
- Удалить: **Удалить** у сервера, потом **Сохранить список**. Его пароль тоже удалится.
- Порядок серверов: тащите за значок ⠿ в таблице «Серверы» на обзоре (сохраняется сразу)
  или здесь — за ⠿ или стрелками ↑ ↓ (сохраняется кнопкой **Сохранить список**). В том же
  порядке стоят карточки каналов. Первый вход в списке — основной: по нему плитка «Трафик
  сейчас идёт», с ним сверяются резервы, его бэкапит панель (если в настройках не выбран
  другой сервер). Если перетаскивание меняет основной вход, панель спросит.
- Кнопка **изменить** в обзоре открывает этот сервер с кнопками **Сохранить и вернуться** и
  **Отмена** — обе возвращают к таблице серверов.
- Пока изменения не сохранены, внизу висит жёлтая полоса с кнопками **Сохранить список** и
  **Отменить**; уйти со страницы без сохранения панель не даст без вопроса.
- id сервера не меняется: к нему привязаны пароль и история графиков. Нужен другой id —
  удалите сервер и добавьте заново.
- Если сервер переустановили на том же IP, панель скажет «ключ сервера изменился» —
  это защита от подмены, см. ниже.

## Новый сервер (мастер)

Пункт **Новый сервер** в меню слева. Шаги: данные сервера и роль → проверка → что ставим →
настройки → связи → установка.

- **Проверка** сначала смотрит, открывается ли порт SSH нового сервера. Если с этого компьютера
  не открывается, она проверяет его с ваших серверов и говорит, где беда: адрес режется на пути из
  России (такой сервер не подойдёт — просите у хостера другой IP), файрвол хостера, SSH на сервере
  или сервер не отвечает вовсе. Если с входов новый выход недоступен, «Далее» не нажмётся.
- **Проверка** дальше только читает: ОС (нужна Ubuntu 24.04), виртуализация (на OpenVZ/LXC AmneziaWG
  не встанет), ресурсы, чужой софт и занятые порты, доступ к GitHub и репозиториям для установки,
  обновления, задержки до ваших серверов и все DC Telegram. Если что-то из этого мешает
  установке, «Далее» не нажмётся.
- **Замер скорости** — по кнопке, гоняет трафик:
  - **Наш замер** (по умолчанию): диск, скачивание по 15 секунд с российского и европейского
    зеркал (адреса меняются в «Настройках» → «Замер скорости») и главное — скорость канала
    между новым сервером и каждым вашим выходом (для нового выхода — с каждым входом) в обе
    стороны. Работает и из РФ, сторонних скриптов не запускает.
  - **bench.sh** и **yabs.sh** (без Geekbench) — стандартные тесты для зарубежных серверов.
    Скачиваются с сайта автора, а если он не открывается — с копии на GitHub.
- **Установка выхода**: на новом сервере `vpn-exit-setup.sh` (AmneziaWG модулем ядра, случайные
  параметры маскировки, BBR, fail2ban), потом на каждом выбранном входе `vpn-add-exit.sh` (туннель
  wgN, исходящее `AWG-ИМЯ`, звено в цепочке на выбранном месте) и, если отметить, звено в цепочке
  Telegram DC5. Перед правкой входов
  делается бэкап базы 3X-UI, при ошибке скрипт её откатывает. Пароль нового выхода входам
  передаётся во временном файле на время подключения и сразу удаляется.
- Можно закрыть браузер — установка идёт в самой панели, страница «Новый сервер» покажет её снова.
  Не выходите из панели в трее, пока установка не закончится. Если что-то упало — исправьте
  и нажмите «Повторить установку»: уже сделанное она пропустит.
- Итоги (порты, ключ AWG, туннели на входах) — в папке `secrets`, журналы — в папке `jobs`.
  Обе остаются у вас на компьютере и в GitHub не попадают.
- **Установка входа** — копия действующего входа из бэкапа: свежий бэкап
  выбранного входа (или файл из `backups`) → `vpn-restore.sh` на новом сервере. Те же клиенты
  с теми же ключами, входящий, порт и путь панели, подписка, цепочка выходов и правило DC5.
  На каждом выходе образца появляется AWG-клиент `<имя>-wg0`, `<имя>-wg1`, … Установщик 3X-UI
  идёт без вопросов и выпускает сертификат Let's Encrypt на IP нового сервера (нужен открытый
  порт 80), чтобы подписка по https заработала сразу. Архив бэкапа и пароли выходов после
  установки с нового сервера удаляются. Ссылки подписки — на экране итога и в `secrets`.
- Вход больше не нужен (например, закончился тест)? На каждом выходе в консоли:
  `bash /root/vpn-remove-client.sh ИМЯ` — уберёт его AWG-клиентов (`--dry` — только показать),
  потом удалите сервер на странице «Серверы и пароли».
- **Замена выхода.** На первом шаге для роли «Выход» есть выбор: **Ещё один выход** (все старые
  остаются) или **Заменить: <выход>** — например, умер один выход, купили другой. При замене:
  - новый ставится как обычный выход, со своими ключами (бэкап старого не нужен);
  - на каждом входе исходящие старого выхода переводятся на новый туннель и
    переименовываются (AWG-Exit1 → AWG-Exit2), поэтому новый оказывается ровно на местах
    старого во всех цепочках — основной и Telegram DC5. Потом туннель до старого
    выключается (конфиг сохраняется рядом с пометкой `.removed-…`);
  - на время замены трафик идёт через остальные выходы, перерыва нет;
  - старый убирается из панели вместе с паролем — только если все входы переключились;
  - на самом старом сервере ничего не меняется: если он жив, его просто отменяют у хостера.
  Вручную на входе то же самое: `REPLACE=IP_старого bash vpn-add-exit.sh ИМЯ IP_нового`.

## Сайты и обходы

Страница **Сайты и обходы** в меню.

- **Проверить сайт** — YouTube, Instagram, Telegram, WhatsApp, Claude кнопкой или любой адрес.
  Панель открывает сайт (у YouTube — ещё видео и картинки) через каждый вход и каждый канал:
  туннель до каждого выхода, плюс прямо с самих выходов. Это только чтение. Итог — таблица
  и вывод простыми словами: где не работает и почему (например, «по пути от выхода его режут по
  имени сайта» или «сайт не пускает адрес этого выхода»).
- Если сайт не открывается через выход, по которому сейчас идёт трафик, а через другие —
  открывается, панель предлагает **обход**: отдельную цепочку для этого сайта через рабочие
  выходы, как у правила Telegram DC5. Ставится только по кнопке, на выбранные входы: правило в
  3X-UI, перед правкой — копия базы (`/etc/x-ui/x-ui.db.before-bypass-…`), если Xray не
  поднимется — откат. Остальной трафик не меняется.
  Цепочку перед установкой можно поменять: порядок стрелками ↑↓, убрать канал ✕, добавить любой
  канал из списка. Трафик идёт по первому исправному каналу сверху вниз.
- **Обходы** — список всех таких цепочек: почему появилась, на каких входах стоит, что показала
  последняя перепроверка. Сами по себе они не перепроверяются: кнопка **Перепроверить**
  смотрит, открывается ли сайт снова через основной выход; если да — обход подсвечивается
  «больше не нужен». Убирается только кнопкой **Убрать обход со всех входов**. Правило Telegram DC5
  (DC5TG) тоже здесь: «Перепроверить» смотрит, открывается ли DC5 с основного выхода, и только
  тогда его стоит убирать.
- **Изменить цепочку** у любого обхода (и у DC5TG) — тот же редактор; **Сохранить на входах**
  меняет цепочку на всех входах, где стоит обход. Само правило (какие сайты) и его место не меняются.
- **+ Новый обход** — сразу поставить обход без проверки: выбрать сервис или вписать адрес сайта,
  собрать цепочку, отметить входы. Если для этого сайта обход уже есть — панель предложит
  изменить цепочку у него.
- Обход по имени сайта работает, только если у входящего в 3X-UI включён sniffing (по умолчанию
  включён); если нет — панель предупредит в журнале.
- **Что режут на входах** — кнопка **Проверить**: каждый вход открывает около 20 сайтов из
  списков блокировок (YouTube, Instagram, Discord, X, GitHub, RuTracker…) прямо, мимо выходов, и
  для неоткрывшихся выясняет, как их режут: **по имени сайта** (TLS рвут, как только видно имя),
  **по адресу** (не открывается даже соединение), **обрыв** (соединение есть, данные обрываются,
  часто на ~16 КБ), **подменяют DNS** / **нет в DNS**, **заглушка** (чужой сертификат). Плюс ya.ru
  для контроля: если не открылся он — у входа проблемы с интернетом, итогу не верьте. Клиентов это
  не касается — их трафик идёт через выходы; это про сам вход: если не открывается GitHub, на нём
  не пройдут установка и обновления. Только чтение, на серверах ничего не ставится. Проверки —
  по образцу censorcheck (vernette, MIT), но своим кодом панели.

## Zapret — сайты с входа напрямую

Страница **Zapret** в меню. Отдельные сайты (например, YouTube) можно пускать не через выходы в Европе, а прямо
с входа: zapret2 ([bol-van/zapret2](https://github.com/bol-van/zapret2)) на входе обходит ТСПУ только для адресов
этого сайта. Клиентов и туннели AWG он не трогает. Всё — по кнопкам с подтверждением.

1. **Zapret на входах** → **Установить**: zapret2 ставится в `/opt/zapret2`, служба остаётся выключенной — пока
   не включена ни одна цель, на входе ничего не меняется. **Выключить всё** / **Удалить** — обратно.
2. **Новая цель**: название и адреса сайта (поддомены входят сами: `googlevideo.com` — это и все серверы видео).
   **Подсказать по первому адресу** — панель смотрит базу geosite на входе (её использует Xray) и показывает,
   в какие наборы входит адрес: например, набор `youtube` — 177 адресов YouTube; **Добавить** вписывает их в цель.
   «Адреса для подбора» — до 6 настоящих адресов, которые реально открываются (`www.youtube.com`,
   `redirector.googlevideo.com`, `i.ytimg.com`).
3. **Подобрать** (шаг 1 у входа): blockcheck2 на входе перебирает способы обхода для адресов подбора, 10–40 минут,
   в фоне. Итог — список стратегий: сколько адресов каждая открыла. Нашлось уже достаточно — **Остановить и взять
   найденное**: подбор остановится (свои временные правила он уберёт сам), панель возьмёт то, что он успел найти.
   Если подбор прервался (перезапуск панели) — **Взять найденное из журнала**.
4. **Включить** (шаг 2): zapret с выбранной стратегией только для адресов цели и только на внешнем интерфейсе входа
   (туннели до выходов он не трогает), потом панель проверяет, открываются ли
   они прямо с входа. Не запустился — прежние настройки возвращаются. Трафик клиентов пока не меняется.
5. **Пустить напрямую** (шаг 3): правило в 3X-UI «адреса цели (только TCP) → напрямую с входа». Как у обходов:
   копия базы, Xray не поднялся — откат. **Вернуть через выходы** — правило убирается.
6. **Автовозврат на выходы** (галочка у цели, включена сразу): каждые 5 минут панель открывает адреса для подбора
   прямо с входа; два провала подряд — сама убирает правило «напрямую», сайт снова идёт через выходы, в журнале —
   запись. Работает, пока запущена панель на компьютере. После этого — **Подобрать заново** и снова включить.

Адреса сайтов цели Xray на входе узнаёт через зашифрованный DNS (DoH 1.1.1.1 и 8.8.8.8) — в обход DNS хостера:
у некоторых хостеров и он, и обычные запросы к 1.1.1.1 адрес YouTube не отдают. Остальные сайты — как обычно.

## Связь (качество каналов)

Страница **Связь** в меню. Проверяет, как ходит трафик по маршрутам «вход → выход» и от этого
компьютера до входов. Только замеры — на серверах ничего не меняется. Запускается только кнопкой.

- **Что проверять собираете сами.** Каждый вход — постоянный блок. Плюсиком добавляете выходы,
  которые хотите проверить с этого входа (можно «все оставшиеся»), ✕ — убрать. Галочка
  **Связь с этого ПК** — проверить путь от вашего домашнего интернета до входа. Набор запоминается.
- **Тесты** (сверху, можно несколько):
  - **Пинги и потери** — около 10 секунд, пара килобайт: пинг с входа до выхода напрямую (мимо
    туннеля) и внутри туннеля AWG, плюс цифры ядра по вашим живым соединениям через туннель
    (сколько пакетов приходится пересылать заново). Если выход не отвечает на пинг, панель
    10 раз подключается к его порту SSH. С этого ПК — 20 пингов (на Windows
    это ~20 секунд) и 10 подключений к порту VLESS.
  - **Скорость** — скачать столько мегабайт, сколько впишете (1–100), через каждый туннель строго
    по очереди; каждый замер — не дольше 20 секунд (не успело — пишется, сколько скачалось).
    2 МБ — быстро, но соединение не успевает разогнаться; 10–25 МБ ближе к настоящей скорости. Если загрузка встаёт на полпути — так и пишется: это похоже на
    блокировку, а не на медленный канал.
  - **Трассировка** — путь по узлам с потерями на каждом: с входа до выхода и с этого ПК до входа.
    Если потери начинаются на каком-то узле и держатся до конца — виноват он. Пропуски только на
    промежуточных узлах — это нормально, они экономят на ответах.
- **Итог** — только то, что не в порядке. Если одна и та же беда на всех проверенных маршрутах
  входа (например, скачет задержка), она пишется один раз у входа.
- Самое полезное сравнение: **напрямую 0% потерь, а в туннеле — потери** значит, душат сам
  туннель; **потери уже напрямую** — дело в сети между серверами, туннель ни при чём.
- «С этого ПК» — путь от вашего домашнего интернета. Телефоны в мобильной сети идут к входу
  другим путём.

## Перевод выхода с Amnezia в Docker на AmneziaWG без Docker

У выходов, где AmneziaWG поставило приложение AmneziaVPN (в Docker), в колонке «Требует внимания»
есть «**AmneziaWG в Docker**». По кнопке с подтверждением выход переводится на AmneziaWG модулем
ядра — как ставит мастер: обновления приходят обычными пакетами (окно
«Обновления»), всё видно в панели.

1. На выходе рядом с контейнером ставится AmneziaWG (своя подсеть, новый порт UDP; если включён
   ufw — порт и пересылка через awg0 открываются). Контейнер пока работает.
2. На каждом входе туннель до этого выхода (тот же wgN) переключается на новый. 3X-UI не
   меняется — места в цепочках и DC5 те же. Если через новый туннель нет выхода, на этом
   входе возвращается старый конфиг и перевод останавливается.
3. Когда все входы на новом — контейнер Amnezia удаляется (с ним — клиенты Amnezia для телефонов
   на этом сервере).

Туннель на каждом входе моргает на несколько секунд, трафик в это время идёт по запасным каналам.
Если у хостера свой фаервол в личном кабинете — откройте в нём новый порт UDP (он в журнале).

## Версия AmneziaWG

- Версия программы и протокола видна у сервера: «AWG … wg0, wg1 · протокол 3.1».
  Протокол — по конфигу: 1.0 — Jc/S1/H1…, 1.5 — добавлены I1–I5, 2.0 — S3/S4 и диапазоны H,
  3.x — защита потока (HeaderProtectionKey, ContentPaddingAddition…).
- AmneziaWG ставится пакетами и обновляется в окне «обновления» сервера. Панель отдельно
  помечает «AmneziaWG: есть обновление» и «AmneziaWG: в памяти старый модуль» — второе значит,
  что пакет уже обновился, а работает прежний модуль ядра: новый заработает после перезагрузки.
- 3X-UI и Xray панель не обновляет — это делается в самой 3X-UI.

## AmneziaWG

Страница **AmneziaWG** в меню — все туннели наглядно, только просмотр:

- сверху — сколько туннелей вход → выход, сколько сейчас на связи, трафик, версия протокола и совпадают ли настройки концов;
- **выходы**: сервер awg0 — порт, адрес, MTU, протокол; кто подключён (какой вход, его адрес в туннеле), на связи ли,
  трафик, когда было последнее рукопожатие; параметры маскировки (Jc, S1–S4, H1–H4, I1–I5, ключ заголовков 3.x…);
- **входы**: каждый туннель wgN — к какому выходу, на связи ли, трафик, параметры и отметка «параметры как у выхода ✓»
  или красное «расходится с выходом: S1, H2» (такие параметры обязаны совпадать, иначе туннель не поднимется);
- кнопка **«Показать конфиг»** — конфиг туннеля как на сервере, но закрытые ключи не передаются с сервера вовсе, а у
  общего ключа заголовков видно только отпечаток.

Панель только читает конфиги и `awg show`, ничего не меняет — кроме пакетов-масок по кнопке. Страница сама обновляется раз в 30 секунд.

**Пакеты-маски (I1).** У каждого туннеля входа — строка «пакеты-маски» с выбором QUIC / STUN / DNS и кнопкой
«Добавить» («Заменить», «Убрать»). Перед каждым рукопожатием вход шлёт пакет, похожий на обычный трафик: начало QUIC
(как браузер открывает сайт), STUN (как начало звонка WebRTC) или DNS-запрос, — и ТСПУ видит знакомый протокол, а не
«шум». Шлёт их только вход, выходу ничего менять не нужно. Каждый раз генерируются новые числа, так что отпечаток у
каждого туннеля свой. Порядок: копия конфига → строка `I1` в `[Interface]` → перезапуск туннеля (моргнёт на пару секунд,
трафик уйдёт по цепочке) → ждём свежее рукопожатие; если за 40 секунд выход «не узнал» вход — вернётся прежний конфиг.
Формы пакетов — по RFC, по образцу генератора из
[awg-containers-and-tools](https://github.com/Vadim-Khristenko/awg-containers-and-tools) (MIT), код свой.

## Качество: как видят адрес, шумные соседи и DNS

Страница **Качество** в меню: у каждого сервера три проверки — «Как видят адрес», «Соседи по подсети» и «DNS», кнопка «Проверить все»
запускает все три для всех серверов. Результаты сохраняются и после перезапуска панели (файл `addrcheck.json`, только на этом компьютере).
Чип «видят как …» у сервера ведёт сюда же. «Как видят адрес» (и карточка в мастере «Новый сервер», рядом с замером скорости):
какой страной адрес считают YouTube, Google, ChatGPT, Gemini, Netflix, Spotify и другие, что пишут
~17 баз геолокации и кому принадлежит сеть (страна регистрации и номер AS). Пометки простыми
словами: «YouTube видит страну: Нидерланды — реклама этой страны», «ChatGPT видит Россию — не работает»,
«сеть зарегистрирована в России, а по базам адрес нидерландский». Итог виден у сервера: «видят как NL · сеть RU».
Там же **репутация адреса**: сколько раз на него жаловались в AbuseIPDB и насколько он «вредный», и оценка
риска мошенничества Scamalytics (0–100). Плохая репутация — это капчи, проверки «вы робот?» и
недоверие банков и магазинов. Это обычные открытые страницы этих сайтов, ключи не нужны.

Строка **ИИ** — пускают ли ChatGPT, Claude, Gemini, Copilot и Grok: ✓ пускает, ✗ «недоступно в вашей
стране», ? — непонятно (капча или сбой, не обязательно запрет). **Тип адреса** — хостинг (дата-центр) или
домашний провайдер, по ip-api и ipinfo; для VPS «хостинг» — это нормально. **VPN/прокси** — помечен ли адрес
как VPN в proxycheck и ipinfo: такие адреса чаще не пускают стриминги и банки. Проверки взяты по образцу
[ipregion-fixed](https://github.com/XaksFlaX/ipregion-fixed) (MIT), но написаны в самой панели.

Внутри — скрипт [ipregion](https://github.com/vernette/ipregion) (MIT). Он лежит в панели проверенной
копией (`server-scripts/third_party/`), а не скачивается с GitHub при каждом запуске, и на сервере
работает от пользователя `nobody`: только запросы к сервисам, ничего не меняет. Займёт 30–60 секунд.
Скрипту нужна программа `jq`. Если её на сервере нет (бывает на входах), остальное всё равно покажется, а под
пометками появится кнопка «Поставить jq и проверить заново» — с подтверждением ставит jq (apt-get install) и повторяет проверку.

### Шумные соседи

Сервер почти всегда делит подсеть /24 (256 адресов) с соседями. Проверка **с этого компьютера** по одному разу
стучится на порт 443 к каждому адресу подсети и смотрит, на чьё имя выдан сертификат:

- **чужой** — сертификат известного сайта (Google, Microsoft, Apple, VK, Max, Яндекс…) на адресе хостера. Почти
  наверняка это такой же VPN с маскировкой Reality. Много таких — подсеть «шумная»: ТСПУ замечает такие и может
  закрыть /24 целиком, вместе с вашим адресом. Для входов это важнее — их видит ТСПУ;
- **настоящий сайт** — DNS его имени (через 1.1.1.1) указывает именно на этот адрес. Если у него TLS 1.3 и h2 —
  он подойдёт для маскировки Reality: сайт по соседству выглядит естественнее, чем «google.com у хостера»;
- прочее — самоподписанные, панели, имена, которые указывают на другие адреса.

С сервера читается только, под какой сайт маскируется ваш Reality (база 3X-UI), — чтобы подсказать, не выдаёт ли
маскировка сама себя. Ничего на серверах не меняется. Займёт около 30 секунд.

### DNS

Третья проверка в «Качестве» — с самого сервера, около 15 секунд, ничего не меняет:

- какие публичные DNS отвечают — Cloudflare, Google, Quad9, AdGuard, Яндекс — и каким способом: обычный (UDP, порт 53),
  зашифрованный DoH (через HTTPS) и DoT (через TLS). У зашифрованных проверяется сертификат: чужой — значит, кто-то
  встаёт посередине;
- подменяет ли DNS хостера ответы и перехватываются ли по дороге обычные запросы к 1.1.1.1 и 8.8.8.8. Для этого
  спрашиваются адреса, заблокированные в РФ (rutracker.org, flibusta.is, linkedin.com), и ответ сравнивается с ответом
  через зашифрованный DNS. Так, например, видно, что на входе обычный DNS подменён и работает только DoH.

Проверка сделана по образцу DNS-проверки из [censorcheck](https://github.com/vernette/censorcheck) (MIT), код свой.

## Веб-панель 3X-UI через панель каскада

У каждого сервера с 3X-UI в таблице «Серверы» есть кнопка **3X-UI**: она открывает веб-панель
3X-UI этого сервера в новой вкладке через SSH — так, будто вы зашли с самого сервера. Логин и
пароль — от 3X-UI, как обычно. Работает и из дома, и с работы (через удалённый доступ).

Поэтому веб-панель можно убрать из интернета, чтобы её не находили сканеры и чтобы не было лишней
двери на сервер:

- «**3X-UI видна из интернета**» в колонке «Требует внимания» — нажмите, подтвердите: панель
  будет слушать только сам сервер (`webListen = 127.0.0.1` в настройках 3X-UI). x-ui
  перезапускается — VPN через этот сервер прерывается на 5–10 секунд. Если после перезапуска
  панель или Xray не поднялись как надо, всё сразу возвращается как было.
- «**3X-UI закрыта из интернета ✓**» в «Сервисах» — так выглядит закрытая. Нажмите, если надо
  снова открыть её в интернет.
- VPN-подключения и подписка от этого не зависят — они работают на своих портах как обычно.
- Ссылки подписки и VLESS, которые копируются из 3X-UI, открытой через панель, — с настоящим
  адресом сервера (а не 127.0.0.1): панель подставляет его сама.
- Если SSH не работает, панель 3X-UI тоже не открыть. Вернуть доступ из интернета можно из
  консоли хостера: `x-ui setting -listenIP 0.0.0.0` и `systemctl restart x-ui`.
- У 3X-UI должен быть свой путь в адресе (webBasePath) — без него кнопки нет.
- «**путь 3X-UI как у «Вход-1»**» — сервер восстановлен из того же бэкапа, и секретный путь в адресе
  у них одинаковый. Такие панели не открыть одновременно: вкладка одной превращается в другую.
  Нажмите — у сервера будет свой случайный путь (логин и пароль 3X-UI прежние, x-ui перезапустится
  на 5–10 с). Новые входы из бэкапа получат такую же подсказку.

## Фаервол

Страница **Фаервол** в меню.

**Проверить** — только смотрит, на серверах ничего не меняется. Для каждого сервера видно, что и на
каких портах слушает и что останется открытым, когда включим фаервол (ufw), а что закроется:

- останутся SSH, входящие 3X-UI, подписка, туннели AmneziaWG;
- закроется лишнее, например веб-панель 3X-UI (она открывается кнопкой «3X-UI» через SSH);
- «**не знаю, что это — закроется**» — порт, который панель не узнала; посмотрите, нужен ли он;
- «само» — порты, которые ufw не касается или открывать не нужно: Docker, DHCP, временные UDP-порты Xray
  (так он сам отправляет UDP наружу; номер каждый раз новый, ответы проходят и при включённом фаерволе);
- заметки: Docker (ufw его не касается), пересылка через туннель на выходе, fail2ban, уже
  существующие правила фаервола;
- «команды, которые выполнит включение» — ровно то, что сделает кнопка.

**Включить фаервол** — по одному серверу, с подтверждением:

1. панель ещё раз проверяет сервер и замеряет, как всё работает сейчас: SSH, каналы через этот
   сервер, на входе — порты VLESS и подписки с вашего компьютера;
2. ставит ufw (если его нет) и заводит на сервере «ремень»: через 5 минут ufw выключится сам;
3. включает ufw с правилами из плана и проверяет всё снова;
4. всё работает — снимает «ремень»; что-то перестало работать — сразу выключает ufw обратно и
   пишет, что именно сломалось; связь с сервером пропала — ufw выключится сам через 5 минут.

Начинайте с резервного входа, потом выход, основной вход — последним. **Выключить** — обратно
(правила останутся записанными). На крайний случай в консоли хостера (VNC): `ufw disable`.

- **Порт 80 и сертификат.** Сертификат Let's Encrypt для подписки и 3X-UI (на IP сервера) живёт около
  6 дней и продлевается сам: Let's Encrypt проверяет сервер по порту 80. Поэтому, если на сервере
  есть такой сертификат, порт 80 в плане фаервола остаётся открытым (в остальное время там ничего
  не слушает). Если фаервол включили без этого правила, панель покажет «сертификат не продлится:
  закрыт порт 80» — нажмите, порт откроется (одно правило ufw), и если продление уже пора — пройдёт сразу.
  Сам VPN от этого сертификата не зависит, а вот обновление подписок на телефонах — да.

### Сети госорганов на входах

На той же странице, у каждого входа — строка **«Сети госорганов»**. Входы видны из России, и их сканируют:
в том числе адреса РКН и ведомств проверяют, что отвечает на порту VLESS. Кнопка **«Не пускать»** ставит на
вход отдельную таблицу nftables, которая отбрасывает **новые подключения** из подсетей госорганов — сканер
просто не получает ответа. То, что вход открывает сам (сайты «напрямую», Госуслуги и т. п.), работает как раньше:
ответы на свои подключения таблица не трогает. ufw, fail2ban и Docker она тоже не задевает. Блокировки и замедления
по дороге это не убирает — только сканеры.

- Список — [C24Be/AS_Network_List](https://github.com/C24Be/AS_Network_List) (около 800 сетей), скачивает его этот
  компьютер и проверяет: только адреса сетей, без слишком крупных и частных.
- **Свои адреса не блокируются никогда:** адрес этого компьютера (как его видит сервер), все, кто в момент включения
  подключён к входу, и список из «Настроек» → «Сети госорганов» → «Свои адреса» (например, рабочий адрес, если он
  вдруг окажется в списке). Если такой адрес в списке есть, панель пишет об этом в ходе включения.
- Включение — как у фаервола: замер (SSH, каналы, порты входа с этого компьютера) → таблица → замер снова; что-то
  сломалось — сразу возвращает как было, связь пропала — вернётся само через 5 минут («ремень»). После перезагрузки
  таблица ставится сама (служба `vpn-dash-govblock`).
- Раз в сутки (меняется в «Настройках») панель скачивает свежий список и, если он поменялся, ставит его туда, где
  защита включена, — с тем же замером и откатом. Итог — в журнале.
- В строке видно, от какого числа список и сколько подключений отброшено. **«Пускать снова»** — убрать таблицу.
- В список входят и сети VK, и некоторые бизнес-сети крупных операторов. Если с какого-то устройства вход перестал
  подключаться, а остальные входы работают, — «Пускать снова» на этом входе или добавьте адрес в «Свои адреса».

## Удалённый доступ (с работы или телефона)

Через Tailscale — закрытую сеть ваших устройств. В интернет панель не открывается: её видят только
компьютеры и телефоны, вошедшие в ваш аккаунт Tailscale, и только после входа по паролю и
одноразовому коду из приложения-аутентификатора.

1. «Настройки» → **Удалённый доступ**: задайте пароль (от 10 символов, не тот, что от серверов),
   нажмите **Создать код**, отсканируйте QR-код в приложении (Google Authenticator, Яндекс Ключ,
   Aegis…) и введите 6 цифр, потом **Включить удалённый доступ**. Панель начнёт слушать второй порт
   (по умолчанию 8788) — только на этом компьютере.
2. Поставьте Tailscale (tailscale.com/download) на домашний и рабочий компьютер, войдите одним
   аккаунтом.
3. На домашнем компьютере в командной строке от администратора: `tailscale serve --bg 8788`.
   Tailscale попросит включить HTTPS-сертификаты — согласитесь. Команда покажет адрес вида
   `https://имя-компьютера.xxxx.ts.net` — его и открывайте с работы.
4. **Не используйте `tailscale funnel`** — он открыл бы панель всему интернету.

Удалённо работает всё, включая консоль. Пароль, коды и включение меняются только на домашнем
компьютере. Все входы и неудачные попытки — в журнале; после 5 ошибок за 15 минут вход
приостанавливается. Активные удалённые сессии видны в «Настройках», их можно завершить.
Выключить — кнопкой там же; убрать адрес из Tailscale — `tailscale serve reset`.

## Если что-то не так

- **«ключ сервера изменился»** — сервер переустановили или подменили. Если переустанавливали
  вы — удалите строку с его IP из `known_hosts` и проверьте снова.
- **«неверный пароль»** — введите пароль заново на странице «Серверы и пароли».
- Страница пишет **«Панель не отвечает»** — панель остановлена (нет значка в трее).
  Запустите `start.bat`.
- `start.bat` закрылся, а значка нет — откройте `dash-run.log` в папке панели и пришлите
  последние строки, или запустите `start.bat console`, чтобы увидеть ошибку в окне.
- **«Панель перезапускалась — обновите страницу»** — нажмите F5.
- Консоль пишет **«[соединение закрыто]»** — сервер разорвал сессию (например, после
  `reboot`). Закройте окно консоли и откройте снова.
- Другой порт вместо 8787: в `start.bat` после строки `cd /d "%~dp0"` добавьте
  `set DASH_PORT=8788`. Автозапуск этот порт не увидит — его тогда лучше выключить.
